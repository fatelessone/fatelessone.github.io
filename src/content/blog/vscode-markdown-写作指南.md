Markdown 的目标不是“排版得多花”，而是让你用接近日常文字的方式，快速写出结构清晰、能长期维护的文档。VS Code 已经内置了 Markdown 编辑、预览、目录和链接检查能力；不需要先安装扩展，也可以开始写。

这篇文章按实际写作顺序来讲。每个语法小节都包含两部分：**输入什么**（可以直接复制）和 **预览效果**（浏览器/VS Code 预览中会看到什么）。读完后，你可以把自己的文章放进这个博客的 `src/content/blog/` 文件夹中发布。

## 第一章：建立第一份文档

### 1. 新建并保存为 `.md`

在 VS Code 中选择“文件 → 新建文本文件”，马上保存，文件名例如：

```text
我的第一篇文章.md
```

关键是最后的 `.md` 扩展名：它告诉 VS Code 这是 Markdown 文件，编辑器会自动启用语法高亮、预览、目录和代码提示。如果右下角语言模式不是 `Markdown`，点击它并选择 `Markdown` 即可。

建议一开始就建立一个小目录：

```text
notes/
├── 我的第一篇文章.md
└── images/
    └── coffee.jpg
```

文档和它专属的图片放在一起，移动或备份时比较不容易遗漏。

### 2. 打开实时预览

写 Markdown 时，最重要的习惯是**边写边预览**。在编辑器中打开 `.md` 文件后，用以下任一种方式：

| 你想做什么 | macOS | Windows / Linux |
| --- | --- | --- |
| 在当前编辑区打开预览 | `⇧⌘V` | `Ctrl+Shift+V` |
| 在右侧打开预览（推荐） | `⌘K V` | `Ctrl+K V` |
| 从命令面板找命令 | `⇧⌘P` | `Ctrl+Shift+P` |

推荐使用“在右侧打开预览”：左边写源文件、右边看结果，改一行就会即时刷新。也可以点击编辑器右上角的预览按钮。

![VS Code 中 Markdown 的左右分栏预览界面](https://code.visualstudio.com/assets/docs/languages/Markdown/preview.png)

*图：VS Code 内置 Markdown Preview。左侧是源代码，右侧是渲染后的文档。*

> 小提醒：快捷键里的 `⌘K V` 不是同时按三个键。先按住 `⌘` 并按 `K`，松开后再按 `V`。

## 第二章：先写结构，再写内容

一篇可读的 Markdown，通常先有标题层级，再填入段落。不要为了“字体变大”而随意跳级；标题应该反映文章结构。

### 3. 标题：用 `#` 划分层级

**输入什么：**

```md
# 我的周末记录

## 上午：去公园

### 路上听到的一首歌

## 下午：整理照片
```

**预览效果：**

#### 我的周末记录

##### 上午：去公园

###### 路上听到的一首歌

##### 下午：整理照片

规则很简单：`#` 后面必须留一个空格；一个 `#` 是一级标题，两个 `##` 是二级标题，依次类推。日常文章通常使用到 `###` 或 `####` 就够了。

建议的文章骨架是：一篇文章只写一个 `#` 级主标题；主要章节用 `##`；章节里的小主题用 `###`。在这个 Astro 博客里，文件顶部的 `title:` 已经是页面主标题，因此正文通常从 `##` 开始即可。

### 4. 段落、换行与分隔线

**输入什么：**

```md
这是第一段。段落中的文字会自然换行；
即使源文件里换了一行，预览中通常仍属于同一段。

这是第二段。段落之间空一整行，阅读节奏会更清楚。

如果真的需要强制换行，可以在上一行末尾加两个空格，  
然后写下一行。

---
```

**预览效果：**

这是第一段。段落中的文字会自然换行；即使源文件里换了一行，预览中通常仍属于同一段。

这是第二段。段落之间空一整行，阅读节奏会更清楚。

如果真的需要强制换行，可以在上一行末尾加两个空格，  
然后写下一行。

---

写文章时，宁可用自然段组织思想，也不要把每一句都强行换行。分隔线 `---` 适合用在大章节之间；一篇短文章用一两次就足够。

### 5. 加粗、斜体、删除线与行内代码

**输入什么：**

```md
这是 **最重要的结论**。

这是 *轻微强调*，也可以写成 _轻微强调_。

原来的计划是 ~~周五发布~~，现在改到周末。

在终端中运行 `npm run dev` 可以启动本地预览。
```

**预览效果：**

这是 **最重要的结论**。

这是 *轻微强调*，也可以写成 _轻微强调_。

原来的计划是 ~~周五发布~~，现在改到周末。

在终端中运行 `npm run dev` 可以启动本地预览。

`**两颗星号**` 用于重点词；`*一颗星号*` 用于较轻的强调；反引号 `` ` `` 最适合包住文件名、命令、变量或很短的代码。不要把一整段话加粗，重点才会失去重点。

## 第三章：把信息写得更易读

### 6. 无序列表、有序列表与嵌套列表

**输入什么：**

```md
- 咖啡豆
- 滤纸
- 牛奶
  - 燕麦奶
  - 全脂牛奶

1. 烧水
2. 研磨咖啡豆
3. 冲泡并记录味道
```

**预览效果：**

- 咖啡豆
- 滤纸
- 牛奶
  - 燕麦奶
  - 全脂牛奶

1. 烧水
2. 研磨咖啡豆
3. 冲泡并记录味道

无序列表可以用 `-`、`*` 或 `+`，但一篇文章中建议统一使用 `-`。嵌套子项在前面空两个或四个空格；有序列表则用 `1.`、`2.`。写步骤时用有序列表，列举并列项目时用无序列表。

### 7. 待办事项

**输入什么：**

```md
- [x] 选好文章主题
- [x] 写完大纲
- [ ] 补一张封面图
- [ ] 检查错别字
```

**预览效果：**

- [x] 选好文章主题
- [x] 写完大纲
- [ ] 补一张封面图
- [ ] 检查错别字

方括号中有空格的 `[ ]` 表示未完成，`[x]` 表示完成。它非常适合项目记录或学习计划；发布的文章中则要适量使用，避免正文看起来像工作清单。

### 8. 引用与提示

**输入什么：**

```md
> 先完成，再完美。
>
> 第二段引用仍然使用 `>` 开头。
```

**预览效果：**

> 先完成，再完美。
>
> 第二段引用仍然使用 `>` 开头。

引用适合放摘录、提醒、结论或需要与正文区分的信息。不要把整篇文章都放进引用块里；它应当是强调，而不是默认段落样式。

## 第四章：链接、图片、代码与表格

### 9. 链接：让文字本身成为入口

**输入什么：**

```md
[Astro 官方文档](https://docs.astro.build/zh-cn/)

也可以直接粘贴：https://code.visualstudio.com/
```

**预览效果：**

[Astro 官方文档](https://docs.astro.build/zh-cn/)

也可以直接粘贴：https://code.visualstudio.com/

链接格式是 `[显示给读者的文字](地址)`。尽量写清链接会带去哪里，例如“Astro 官方文档”，不要只写“点这里”。URL 中有空格时请改用 `%20`，或先确认目标地址是否正确。

### 10. 图片：先写替代文字，再写路径

**输入什么：**

```md
![一杯手冲咖啡](./images/coffee.jpg)
```

**预览效果：**

`![替代文字](图片路径)` 的结构和链接很像，只是在最前面多了一个感叹号。替代文字会在图片无法加载时显示，也会帮助读屏软件理解图片内容，因此不要留空或只写“图片”。

在 VS Code 里，把图片文件拖进 Markdown 编辑器、或直接粘贴本地图片文件，编辑器可以自动插入图片链接；也可以从命令面板运行 **Markdown: Insert Image from Workspace**。下图展示了把文件粘贴进文档时生成链接的方式。

![VS Code 将粘贴的文件转换为 Markdown 链接](https://code.visualstudio.com/assets/docs/languages/Markdown/markdown-paste-link.png)

*图：VS Code 可以协助插入工作区内的文件链接。*

#### 在这个博客中放图片

本博客推荐把公共图片放到 `public/images/`，然后在文章中这样写：

```md
![咖啡桌上的笔记本](/images/coffee.jpg)
```

注意路径开头的 `/`：它从网站的 `public` 根目录找图片。若文章专属图片和 `.md` 文件放在同一个目录，则可用 `./images/coffee.jpg` 这类相对路径。先在 VS Code 的预览里检查一次，再打开博客页面检查一次，能最快发现路径问题。

### 11. 代码：短代码用反引号，多行代码用围栏

**输入什么：**

````md
行内命令是 `npm run build`。

```bash
npm install
npm run dev
```

```js
const greeting = 'Hello, Markdown!';
console.log(greeting);
```
````

**预览效果：**

行内命令是 `npm run build`。

```bash
npm install
npm run dev
```

```js
const greeting = 'Hello, Markdown!';
console.log(greeting);
```

三颗反引号围住多行代码；紧跟在开头反引号后的 `bash`、`js`、`html`、`css` 是语言名称，能让预览和博客获得更准确的语法高亮。代码块里不会解析 Markdown，所以很适合展示原始写法。

如果要在代码块中展示三颗反引号本身，就像上面的“输入什么”那样，外层改用四颗反引号即可。

### 12. 表格：适合做对比，不适合塞长段落

**输入什么：**

```md
| 命令 | 用途 | 什么时候用 |
| --- | --- | --- |
| `npm run dev` | 启动本地预览 | 写作与调试时 |
| `npm run build` | 生成发布文件 | 推送前检查时 |
```

**预览效果：**

| 命令 | 用途 | 什么时候用 |
| --- | --- | --- |
| `npm run dev` | 启动本地预览 | 写作与调试时 |
| `npm run build` | 生成发布文件 | 推送前检查时 |

第一行是表头；第二行的 `---` 是分隔行；之后每行是一条数据。竖线两边留不留空格都能工作，但留空格可读性更好。表格最适合比较参数、版本、快捷键和清单；长篇解释仍然用段落或列表。

### 13. 可选进阶：流程图与数学公式

VS Code 的 Markdown Preview 支持 Mermaid 图表和 KaTeX 数学公式。它们适合技术笔记：

````md
```mermaid
flowchart LR
  A[写 Markdown] --> B[VS Code 预览]
  B --> C[发布到博客]
```

行内公式：$E = mc^2$
````

不过要区分两件事：**VS Code 能预览，不代表每个网站都已配置渲染**。这个博客当前普通 Markdown 文章可直接使用前面所有基础语法；若你要在博客里正式发布 Mermaid 或数学公式，先确认 Astro 项目已添加对应的 Markdown/Remark 插件，再使用它们。

## 第五章：VS Code 中真正省时间的功能

### 14. 用大纲快速检查文章结构

打开左侧活动栏的“资源管理器”，在 Markdown 文件下方找到 **Outline（大纲）**。它会读取你写的所有 `#` 标题；点击任意标题就能跳到对应位置。

![VS Code 的 Markdown Outline 视图](https://code.visualstudio.com/assets/docs/languages/Markdown/markdown-outline-view.png)

*图：大纲会跟随标题层级生成目录，是检查文章结构最快的方法。*

另一个快捷方式是：macOS 按 `⇧⌘O`，Windows/Linux 按 `Ctrl+Shift+O`，可在当前文章的标题之间快速跳转。写完大纲后，先看一眼 Outline：如果某个标题突然缩得很深，通常是 `#` 数量写错了。

### 15. 使用补全与内置片段

在空行输入 `#`、`-`、`>` 等符号后，VS Code 常会给出 Markdown 建议。也可以主动按：macOS `⌃Space`，Windows/Linux `Ctrl+Space`，呼出建议列表。

例如输入 `!` 再选择图片相关建议，可以少记一点格式；输入 `table` 等片段提示后，再按 `Tab`，可更快开始一张表。片段是加速工具，不是必须记忆的命令：刚开始时优先理解前面每种格式的结构。

### 16. 安全地改标题、移动文件

标题常常会被其他位置链接。需要改标题时，把光标放在标题文本上，按 `F2`（macOS 如有功能键设置，可使用 `fn + F2`），输入新标题并确认；VS Code 会尝试更新同一工作区内指向该标题的链接。

移动或重命名 `.md` 文件时，建议在设置中搜索 `Markdown: Update Links On File Move`，将其设为 `prompt`。以后文件移动时，VS Code 会询问是否更新引用它的链接，而不是悄悄留下失效链接。

### 17. 让编辑器帮助你发现问题

打开设置，搜索 `Markdown Validate Enabled`，确认它处于启用状态。这样 VS Code 会检查 Markdown 中的链接、图片和标题锚点等常见问题。

你也可以在项目的 `.vscode/settings.json` 中保存下面的偏好（没有这个文件夹可以新建）：

```json
{
  "markdown.validate.enabled": true,
  "markdown.updateLinksOnFileMove.enabled": "prompt",
  "[markdown]": {
    "files.trimTrailingWhitespace": false
  }
}
```

最后一项的用途是保留 Markdown 行末空格：少数情况下，行末两个空格正是“强制换行”的语法。若你从不用这种换行方式，也可以不加这项。

## 第六章：把文章发布到这个 Astro 博客

VS Code 的 Markdown Preview 负责让你写得舒服；这个 Astro 项目负责把 `.md` 文件变成博客页面。下面是本博客实际采用的流程。

### 18. 新建文章文件

在 VS Code 左侧文件树中进入：

```text
src/content/blog/
```

新建一个名字清晰的文件，例如：

```text
我的第一篇随笔.md
```

每篇博客的第一部分都必须是 Frontmatter，也就是一对 `---` 包起来的文章信息。复制这个模板并改成自己的内容：

```md
---
title: 我的第一篇随笔
description: 用一句话说明这篇文章写了什么。
pubDate: 2026-09-19
tags: [随笔, 生活]
---

## 正文从这里开始

写下第一段内容。
```

这些字段的作用：

| 字段 | 必填 | 写什么 |
| --- | --- | --- |
| `title` | 是 | 文章标题，会显示在文章页和列表页 |
| `description` | 是 | 文章摘要，会显示在文章列表中 |
| `pubDate` | 是 | 发布日期，格式固定为 `YYYY-MM-DD` |
| `tags` | 是 | 用方括号包住的标签，例如 `[读书, 随笔]` |
| `updatedDate` | 否 | 修改日期，例如 `updatedDate: 2026-09-20` |
| `draft` | 否 | 写 `draft: true` 时不公开显示，适合未完成草稿 |

Frontmatter 中的冒号后要有一个空格。标题或摘要含有特殊符号、冒号时，最稳妥的写法是加引号，例如 `title: "关于 Markdown：一份笔记"`。

### 19. 在本地检查，再发布

打开 VS Code 的终端（菜单“终端 → 新建终端”），在项目根目录运行：

```bash
npm run dev
```

终端会显示一个本地地址。打开它，检查：文章是否出现在首页、标题有没有断行异常、图片能否加载、标签是否正确。写完或准备推送前，再运行：

```bash
npm run build
```

这一步会把整个网站构建一遍；若 Frontmatter 少字段、日期格式错误或 Markdown 有导致构建失败的问题，终端会告诉你文件和行号。构建成功后再执行自己的 Git 提交与推送流程即可。

### 20. 一套舒服的写作顺序

1. 在 `src/content/blog/` 新建 `.md` 文件，先填 Frontmatter。
2. 用 `##` 和 `###` 写大纲，在 Outline 里检查结构。
3. 填正文；每写完一个章节就看右侧 Markdown Preview。
4. 把图片放进 `public/images/`，补上有意义的替代文字。
5. 用本地博客页面检查实际效果。
6. 运行 `npm run build`，成功后再提交与推送。

VS Code 预览擅长检查**语法和写作过程**；本地博客页面擅长检查**真实网站的字体、图片尺寸、文章布局与链接**。两个都看一遍，发布时最安心。

## 第七章：常见问题与速查表

### 为什么我写的格式没有生效？

- 确认文件后缀是 `.md`，不是 `.txt`。
- 确认符号后有空格：例如标题应写 `## 标题`，而不是 `##标题`。
- 代码块的开头和结尾反引号数量必须一致，而且要单独占一行。
- 图片不显示时，先检查文件名大小写、路径和扩展名；`photo.jpg` 与 `photo.JPG` 不是同一个名字。
- 表格乱掉时，先确认第二行有 `| --- | --- |` 这样的分隔行。

### 最常用语法速查

| 想写什么 | 输入 |
| --- | --- |
| 二级标题 | `## 标题` |
| 加粗 | `**重点**` |
| 斜体 | `*强调*` |
| 行内代码 | `` `npm run dev` `` |
| 无序列表 | `- 项目` |
| 有序列表 | `1. 步骤` |
| 待办项 | `- [ ] 未完成` |
| 引用 | `> 一句话` |
| 链接 | `[文字](https://example.com)` |
| 图片 | `![替代文字](./image.jpg)` |
| 代码块 | ```` ```js ... ``` ```` |
| 分隔线 | `---` |

如果只记住一句话：**先写清标题层级，再用预览验证效果。** Markdown 并不要求你背完所有标记；需要哪一种，就回到这篇文章复制哪一种。写得多了，它会自然变成肌肉记忆。
